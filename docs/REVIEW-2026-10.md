## Payment findings and fixes

Previously a successful event could omit `amount` or `currency` and still confirm an order. Captured events now require those fields, a payment/order ID and captured status. The server compares against its own integer-paise total, never a browser amount.

A failed event formerly read PENDING_PAYMENT and then performed an unconditional update; a concurrent success could win between the read and write and be overwritten as FAILED. The failure write now conditions on pending order and non-paid payment state. Cancelled-order late payment updates are conditional too.

Two simultaneous success events could both trigger downstream notifications even though the transaction itself only moved stock once. The transition now reports whether it actually changed state; only the winning transition schedules side effects. This does not provide durable delivery across process crashes: an outbox remains recommended.

Razorpay documents asynchronous, at-least-once, possibly out-of-order events. Unknown local orders now return 503 to allow a later retry instead of acknowledging and discarding a legitimate early delivery. Alert on prolonged unknown-order retries, since a webhook pointed at the wrong environment will never resolve by itself.

## SEO and answer-engine approach

Search engines need accurate, server-rendered public content and structured data matching the visible page. Fixed stock markup no longer tells crawlers every priced variant is in stock. No fake review scores, unavailable delivery promises, product prices or certification facts were introduced. The FAQ is useful visible content; ordinary commerce FAQ markup does not imply eligibility for Google's restricted FAQ rich results. `llms.txt` is informational, not an AI-ranking mechanism.

3. **Security backlog:** staff MFA/access policy, nonce CSP with full hosted-payment browser regression, periodic penetration tests, and monitoring the unpatched dev-only braces advisory. Current dependency path is `eslint-config-next -> @next/eslint-plugin-next -> fast-glob -> micromatch -> braces`; never expose linting over an untrusted public input service. No audit suppression was added.
4. **Product backlog:** customer OTP/account/address book, favourites, transaction email delivery reporting, a product-specific purchase/review workflow as business priorities dictate. Existing refund/credit-note work still needs the external provider/accountant process.
